1. Cấu Trúc Vật Lý & Cơ Chế Cấp Phát Bộ Nhớ Trong SQL Server

Cách SQL Server tổ chức các byte trên đĩa cứng và trên bộ nhớ RAM (Buffer Pool).

Phân loại tệp tin CSDL vật lý:

  • 1. Primary Data File (.mdf): Tệp dữ liệu chính, điểm khởi đầu của CSDL. Lưu trữ con trỏ tới tất cả các tệp khác, metadata hệ thống và dữ liệu người dùng. Mỗi CSDL chỉ có chính xác 1 tệp .mdf. Dung lượng tối thiểu phải bằng CSDL khuôn mẫu model (khoảng 1.5MB).
  • 2. Secondary Data File (.ndf): Tệp dữ liệu phụ, không bắt buộc. Được sử dụng khi CSDL quá lớn, cho phép phân tách bảng và chỉ mục sang các ổ đĩa cứng vật lý khác nhau (striping) để tăng tốc độ đọc/ghi I/O đồng thời.
  • 3. Transaction Log File (.ldf): Tệp nhật ký giao tác. Ghi lại từng thao tác sửa đổi nhị phân. Không lưu bảng hay chỉ mục. Phải có ít nhất 1 tệp .ldf cho mỗi CSDL.

Đơn vị lưu trữ vi mô: Page & Extent

  • Data Page (8 KB = 8,192 bytes): Là đơn vị I/O cơ sở. Mọi thao tác đọc/ghi đĩa đều diễn ra theo từng Page nguyên vẹn.
    • Page Header (96 bytes): Lưu Page ID, Type, Free Space, LSN...
    • Data Rows: Dữ liệu thực tế. Độ dài tối đa 1 dòng là 8,060 bytes.
    • Row Offset Table (cuối trang): Mảng 2-byte trỏ đến vị trí từng dòng.
  • Extent (64 KB = 8 Data Pages liên tục):

    • Mixed Extent: Chứa trang của tối đa 8 đối tượng bảng khác nhau (tiết kiệm không gian cho bảng nhỏ).

    • Uniform Extent: Toàn bộ 8 trang thuộc sở hữu của duy nhất 1 bảng khi bảng đó đã phát triển đủ lớn.

Cơ Chế Giao Tác ACID, Write-Ahead Logging (WAL) & Tiến Trình Checkpoint

SQL Server không bao giờ ghi trực tiếp dữ liệu sửa đổi xuống file .mdf ngay lập tức vì ghi ngẫu nhiên (random disk write) rất chậm. Chu trình chuẩn diễn ra như sau:

BƯỚC 1: SỬA RAM Dữ liệu được đọc vào Buffer Pool. Khi có lệnh Update, trang bị sửa thành Dirty Page trên RAM.
BƯỚC 2: GHI LOG (WAL) Hành động sửa đổi bắt buộc phải ghi tuần tự vào file .ldf trên đĩa trước khi báo Commit thành công.
BƯỚC 3: CHECKPOINT Định kỳ, Checkpoint Process quét toàn bộ Dirty Pages trên RAM và đẩy đồng loạt xuống file .mdf.
BƯỚC 4: RECOVERY Khi máy sập: Giao dịch đã commit → Roll Forward (tạo lại). Chưa commit → Roll Back (hủy bỏ).

2. Lý Thuyết Toàn Vẹn Thực Thể, Toàn Vẹn Tham Chiếu & Chuẩn Hóa

Cơ sở lý thuyết phụ thuộc hàm (Armstrong) và chi tiết kỹ thuật của các ràng buộc T-SQL.

Hệ Tiên Đề Armstrong & Khóa (Keys):

• Siêu khóa (Superkey): Tập thuộc tính xác định duy nhất mỗi bộ (dòng) trong bảng.

• Khóa chỉ định / Khóa dự tuyển (Candidate Key): Siêu khóa tối tiểu (không thể bớt bất kỳ thuộc tính nào mà vẫn duy trì tính duy nhất).

• Khóa chính (Primary Key): Khóa được chọn để cài đặt vật lý. Không chứa NULL.

• 3 Luật Armstrong cơ bản:

  • Phản xạ: Nếu Y ⊆ X thì X → Y.
  • Tăng trưởng: Nếu X → Y thì XZ → YZ.
  • Bắc cầu: Nếu X → Y và Y → Z thì X → Z.

Hành Vi Khóa Ngoại (Foreign Key Referential Actions):

Khi một dòng ở bảng cha bị xóa (ON DELETE) hoặc cập nhật (ON UPDATE), bảng con có thể xử lý theo 4 cơ chế:

  • NO ACTION (Mặc định): Báo lỗi và hủy bỏ toàn bộ câu lệnh nếu có dữ liệu con đang tham chiếu.
  • CASCADE: Tự động xóa hoặc cập nhật theo dây chuyền các dòng con liên quan.
  • SET NULL: Đặt giá trị cột khóa ngoại ở bảng con thành NULL (nếu cột cho phép NULL).
  • SET DEFAULT: Gán lại giá trị ngầm định đã cấu hình của cột khóa ngoại.

3. Đại Số Quan Hệ Toán Học & Pipeline Thực Thi Truy Vấn SELECT

Cơ chế máy tính thực hiện các phép chọn, chiếu, tích Descartes và luồng xử lý truy vấn.

Các Phép Toán Đại Số Quan Hệ Cơ Bản:

• Phép chọn σ (Restriction / Selection): Lấy ra các bộ (dòng) thỏa điều kiện vị từ: σLuong > 500(NHANVIEN) → Tương đương mệnh đề WHERE.

• Phép chiếu π (Projection): Rút trích theo chiều dọc các cột mong muốn: πHoTen, Luong(NHANVIEN) → Tương đương danh sách sau SELECT.

• Tích Descartes (×): Ghép mọi dòng của bảng R với mọi dòng của bảng S (m dòng × n dòng).

• Phép nối kết θ (Join): Thực hiện tích Descartes sau đó áp dụng phép chọn theo điều kiện θ so sánh thuộc tính: R ⋈R.MaDV = S.MaDV S.

• Phép kết tự nhiên (Natural Join): Phép kết bằng trên tất cả các thuộc tính có cùng tên giữa 2 quan hệ và loại bỏ các cột trùng lặp.

Quy Trình Xử Lý Thực Tế 8 Bước (Query Execution Order):

(1) FROM & JOIN: Nạp các bảng và tạo tích Descartes / nối On
(2) WHERE: Loại bỏ các dòng không thỏa biểu thức logic
(3) GROUP BY: Thu gọn các dòng cùng giá trị thành 1 đại diện nhóm
(4) HAVING: Lọc bỏ các nhóm không đạt tiêu chuẩn hàm nhóm
(5) SELECT: Tính toán biểu thức, lấy danh sách cột, gán Alias
(6) DISTINCT: Khử các dòng trùng lặp trong tập kết quả
(7) ORDER BY: Sắp xếp các dòng (tiêu tốn bộ nhớ tempdb)
(8) TOP / OFFSET: Rút trích số lượng dòng theo yêu cầu phân trang

4. Khung Nhìn (View) & Thủ Tục Lưu Trữ (Stored Procedure) Chuyên Sâu

Nguyên tắc biên dịch, cơ chế an toàn dữ liệu và tối ưu hóa truy vấn.

Khung Nhìn (VIEW) Chuyên Sâu:

View là một bảng logic được định nghĩa bởi câu truy vấn SELECT. Bản thân View không lưu trữ dữ liệu (trừ Indexed View).

  • • WITH SCHEMABINDING: Khóa cấu trúc của các bảng gốc tham gia vào View, ngăn cấm ai đó dùng lệnh ALTER hoặc DROP bảng gốc làm hỏng View.
  • • WITH CHECK OPTION: Đảm bảo mọi thao tác INSERT hoặc UPDATE thông qua View bắt buộc phải thỏa mãn mệnh đề WHERE của View đó.
  • • Giới hạn DML trên View: Chỉ có thể INSERT/UPDATE vào duy nhất 1 bảng gốc sau mệnh đề FROM tại một thời điểm; View chứa GROUP BY, DISTINCT, hàm tổng hợp không được phép sửa dữ liệu trực tiếp.

Stored Procedure & Recompilation:

Stored Procedure được biên dịch và sinh ra sơ đồ thực thi (Execution Plan) lưu trong vùng đệm bộ nhớ đệm (Procedure Cache).

  • • Biến đầu vào & đầu ra (OUTPUT): Cho phép trả về kết quả số lượng, trạng thái về ứng dụng mà không cần SELECT toàn bộ bảng.
  • • Tối ưu bảo mật: Người dùng chỉ cần cấp quyền GRANT EXECUTE ON sp_Name mà không cần cấp quyền SELECT hay UPDATE trực tiếp trên bảng.
  • • Tái biên dịch (Recompile): Dùng sp_recompile 'TenBang' hoặc WITH RECOMPILE khi dữ liệu trong bảng biến động lớn làm sai lệch chỉ mục.

5. Chiến Lược Backup / Restore & Phục Hồi Điểm Thời Gian (Point-in-Time)

Phân biệt toán học và thứ tự khôi phục dữ liệu không để mất giao dịch.

Full Database Backup

Chép lại toàn bộ dữ liệu, schema, cấu trúc chỉ mục và một phần log hoạt động để đưa CSDL về trạng thái nhất quán. Là nền tảng bắt buộc trước mọi loại backup khác.

Differential Backup

Chỉ sao lưu các Data Page bị biến đổi kể từ lần Full Backup gần nhất (dựa trên bitmap kiểm tra thay đổi). Giảm thời gian sao lưu và tiết kiệm dung lượng đĩa đáng kể.

Transaction Log Backup

Chỉ sao lưu các bản ghi log phát sinh kể từ lần Log Backup gần nhất và cắt tỉa (truncate) phần log không hoạt động. Cho phép phục hồi tới từng giây (Point-in-Time).

Thứ tự chuẩn khi thực hiện Phục Hồi Thảm Họa (Disaster Recovery Pipeline):
1. RESTORE DATABASE CSDL FROM Full_Backup WITH NORECOVERY; -- Chưa mở CSDL
2. RESTORE DATABASE CSDL FROM Diff_Backup WITH NORECOVERY; -- Áp bản Diff mới nhất
3. RESTORE LOG CSDL FROM Log_Backup_1 WITH NORECOVERY; -- Áp các log tuần tự
4. RESTORE LOG CSDL FROM Log_Backup_N WITH RECOVERY; -- Mở CSDL cho người dùng

-- BƯỚC 4: KỸ THUẬT TRUY VẤN DỮ LIỆU T-SQL CHUYÊN SÂU
-- =========================================================================

-- [Truy vấn 1]: INNER JOIN với bộ lọc dòng WHERE và bí danh AS
-- Lấy danh sách sản phẩm có đơn giá >= 400 và sắp xếp giảm dần theo giá
SELECT 
    SP.MaSP,
    SP.TenSP,
    SP.DonGia,
    SP.SoLuongTon,
    LH.TenLoai
FROM SANPHAM AS SP
INNER JOIN LOAIHANG AS LH ON SP.MaLoai = LH.MaLoai
WHERE SP.DonGia >= 400.00
ORDER BY SP.DonGia DESC;
GO

-- [Truy vấn 2]: LEFT OUTER JOIN để không bỏ sót ngành hàng chưa có sản phẩm
SELECT 
    LH.MaLoai,
    LH.TenLoai,
    COUNT(SP.MaSP) AS SoLuongMatHang,
    ISNULL(SUM(SP.SoLuongTon), 0) AS TongTonKho,
    ISNULL(AVG(SP.DonGia), 0) AS DonGiaTrungBinh
FROM LOAIHANG AS LH
LEFT JOIN SANPHAM AS SP ON LH.MaLoai = SP.MaLoai
GROUP BY LH.MaLoai, LH.TenLoai
HAVING COUNT(SP.MaSP) >= 0; -- Hiển thị cả loại có 0 sản phẩm
GO

-- [Truy vấn 3]: Gom nhóm GROUP BY kèm HAVING với nhiều điều kiện hàm nhóm
-- Chỉ hiển thị những loại hàng có từ 2 sản phẩm trở lên VÀ đơn giá trung bình > 200
SELECT 
    LH.TenLoai,
    COUNT(SP.MaSP) AS TongSoSP,
    MAX(SP.DonGia) AS GiaCaoNhat,
    AVG(SP.DonGia) AS GiaTrungBinh
FROM LOAIHANG AS LH
INNER JOIN SANPHAM AS SP ON LH.MaLoai = SP.MaLoai
GROUP BY LH.TenLoai
HAVING COUNT(SP.MaSP) >= 2 AND AVG(SP.DonGia) > 200.00;
GO

-- [Truy vấn 4]: Subquery vô hướng (Scalar Subquery)
-- Tìm các sản phẩm có đơn giá cao hơn mức giá trung bình của toàn bộ cửa hàng
SELECT 
    MaSP,
    TenSP,
    DonGia
FROM SANPHAM
WHERE DonGia > (
    SELECT AVG(DonGia) 
    FROM SANPHAM
);
GO

-- [Truy vấn 5]: Subquery với toán tử tập hợp '> ALL'
-- Tìm sản phẩm có giá cao hơn TẤT CẢ các sản phẩm thuộc loại 'L003' (Phụ kiện)
SELECT 
    MaSP,
    TenSP,
    DonGia,
    MaLoai
FROM SANPHAM
WHERE DonGia > ALL (
    SELECT DonGia 
    FROM SANPHAM 
    WHERE MaLoai = 'L003'
);
GO

-- =========================================================================
CREATE VIEW vw_BaoCaoKhoHang (MaLoai, TenLoai, SoLuongMatHang, TongGiaTriKho)
AS
SELECT 
    LH.MaLoai,
    LH.TenLoai,
    COUNT(SP.MaSP),
    ISNULL(SUM(SP.DonGia * SP.SoLuongTon), 0)
FROM LOAIHANG LH
LEFT JOIN SANPHAM SP ON LH.MaLoai = SP.MaLoai
GROUP BY LH.MaLoai, LH.TenLoai;
GO

-- Truy vấn báo cáo thông qua View
SELECT * FROM vw_BaoCaoKhoHang WHERE TongGiaTriKho > 0;
GO

-- =========================================================================
-- BƯỚC 6: XÂY DỰNG STORED PROCEDURE CẬP NHẬT DỮ LIỆU CHUẨN DOANH NGHIỆP
-- Yêu cầu: Kiểm tra đầu vào, kiểm tra khóa ngoại, bẫy lỗi và trả thông báo
-- =========================================================================
CREATE PROCEDURE sp_CapNhatGiaVaKho
    @p_MaSP int,
    @p_DonGiaMoi numeric(10,2),
    @p_SoLuongNhap int
AS
BEGIN
    SET NOCOUNT ON; -- Không trả về số dòng ảnh hưởng để tiết kiệm băng thông

    -- Kiểm tra 1: Xác thực đơn giá
    IF (@p_DonGiaMoi <= 0)
    BEGIN
        PRINT N'Thất bại: Đơn giá mới phải là số dương (> 0)!';
        RETURN;
    END;

    -- Kiểm tra 2: Xác thực số lượng nhập thêm
    IF (@p_SoLuongNhap < 0)
    BEGIN
        PRINT N'Thất bại: Số lượng nhập kho không được là số âm!';
        RETURN;
    END;

    -- Kiểm tra 3: Xác thực sự tồn tại của sản phẩm
    IF NOT EXISTS (SELECT 1 FROM SANPHAM WHERE MaSP = @p_MaSP)
    BEGIN
        PRINT N'Thất bại: Mã sản phẩm không tồn tại trong hệ thống!';
        RETURN;
    END;

    -- Thực hiện cập nhật
    UPDATE SANPHAM
    SET DonGia = @p_DonGiaMoi,
        SoLuongTon = SoLuongTon + @p_SoLuongNhap
    WHERE MaSP = @p_MaSP;

    PRINT N'Thành công: Đã cập nhật đơn giá và cộng dồn số lượng tồn kho!';
END;
GO

-- Thử nghiệm các kịch bản kiểm thử:
-- Test case 1: Giá âm (Sẽ bị chặn)
EXEC sp_CapNhatGiaVaKho @p_MaSP = 1, @p_DonGiaMoi = -100, @p_SoLuongNhap = 5;

-- Test case 2: Hợp lệ (Cập nhật sản phẩm 1 lên giá 350, nhập thêm 10 cái)
EXEC sp_CapNhatGiaVaKho @p_MaSP = 1, @p_DonGiaMoi = 350.00, @p_SoLuongNhap = 10;
GO

-- Kiểm tra lại bảng SANPHAM để thấy kết quả
SELECT * FROM SANPHAM WHERE MaSP = 1;
GO

Truy Vấn T-SQL & Xây Dựng Khung Nhìn (VIEW)

Yêu cầu cần đạt:

  • Truy vấn kết nối INNER JOIN nhân viên và đơn vị có lương >= 600.
  • Gom nhóm GROUP BY đơn vị có lương TB > 600 (dùng HAVING).
  • Truy vấn lồng: Lương > trung bình công ty, lương > ALL đơn vị '02'.
  • Tạo 2 khung nhìn: vw_NhanVien_DonVi và vw_ThongKeDonVi.
USE QL_CONGTY;
GO

-- 1. INNER JOIN
SELECT NV.HoTen, NV.Luong, DV.TenDV
FROM NHANVIEN NV
INNER JOIN DONVI DV ON NV.MaDV = DV.MaDV
WHERE NV.Luong >= 600;
GO

-- 2. GROUP BY & HAVING
SELECT MaDV, MAX(Luong) AS MaxLuong, AVG(Luong) AS LuongTB
FROM NHANVIEN
GROUP BY MaDV
HAVING AVG(Luong) > 600;
GO

-- 3. SUBQUERY
SELECT MaNV, HoTen, Luong
FROM NHANVIEN
WHERE Luong > (SELECT AVG(Luong) FROM NHANVIEN);
GO

SELECT MaNV, HoTen, Luong
FROM NHANVIEN
WHERE Luong > ALL (
    SELECT Luong 
    FROM NHANVIEN 
    WHERE MaDV = '02'
);
GO

-- 4. VIEW
CREATE VIEW vw_NhanVien_DonVi
AS
SELECT NV.MaNV, NV.HoTen, DV.TenDV, NV.Luong
FROM NHANVIEN NV
INNER JOIN DONVI DV ON NV.MaDV = DV.MaDV;
GO

CREATE VIEW vw_ThongKeDonVi (TenDV, SoNhanVien, TongLuong)
AS
SELECT DV.TenDV, COUNT(NV.MaNV), SUM(NV.Luong)
FROM DONVI DV
INNER JOIN NHANVIEN NV ON DV.MaDV = NV.MaDV
GROUP BY DV.TenDV;
GO

SELECT * FROM vw_ThongKeDonVi;
GO

Stored Procedure & Quản Trị Backup/Restore

Yêu cầu cần đạt:

  • Viết Stored Procedure sp_ThemNhanVien có kiểm tra tính hợp lệ của lương trước khi INSERT.
  • Tạo Backup Device logic: thietbi_backup_congty qua sp_addumpdevice.
  • Thực hiện lệnh Full Backup (vào Device và trực tiếp ra tệp tin .BAK).
  • Thực hiện lệnh RESTORE DATABASE WITH REPLACE để khôi phục trạng thái.
USE QL_CONGTY;
GO

-- 1. Stored Procedure
CREATE PROCEDURE sp_ThemNhanVien
    @MaNV char(10),
    @HoTen nvarchar(50),
    @Luong numeric(10,2),
    @MaDV char(2)
AS
BEGIN
    IF (@Luong <= 500)
    BEGIN
        PRINT N'Lỗi: Lương nhân viên phải lớn hơn 500!';
        RETURN;
    END

    INSERT INTO NHANVIEN (MaNV, HoTen, Luong, MaDV)
    VALUES (@MaNV, @HoTen, @Luong, @MaDV);

    PRINT N'Thêm nhân viên mới thành công!';
END;
GO

EXEC sp_ThemNhanVien 'NV099', N'Trần Văn An', 750, '01';
GO

-- 2. Tạo thiết bị Backup logic
USE master;
GO
EXEC sp_addumpdevice 'disk', 'thietbi_backup_congty', 'C:\Backup\QL_CONGTY.BAK';
GO

-- 3. Sao lưu Full Database
BACKUP DATABASE QL_CONGTY 
TO thietbi_backup_congty 
WITH INIT;
GO

BACKUP DATABASE QL_CONGTY 
TO DISK = N'C:\Backup\QL_CONGTY_Full.bak' 
WITH INIT;
GO

-- 4. Phục hồi dữ liệu
USE master;
GO
RESTORE DATABASE QL_CONGTY 
FROM thietbi_backup_congty 
WITH REPLACE;
GO

Bài Tập Tự Luyện Về Nhà (Không Kèm Code Mẫu)

Sinh viên tự đọc yêu cầu, phân tích quan hệ và tự hoàn thiện script T-SQL vào khung soạn thảo. Nhấn "Tải File .SQL Nộp Bài" để nộp bài làm cho giảng viên.

Đề Số 01 Hạn nộp: Buổi học kế tiếp

Quản Lý Điểm Sinh Viên (QL_DIEM)

Cho lược đồ cơ sở dữ liệu gồm 4 bảng sau:

• KHOA (MaKhoa char(4), TenKhoa nvarchar(50))

• MONHOC (MaMH char(4), TenMH nvarchar(50), SoTinChi int)

• SINHVIEN (MaSV char(10), HoTen nvarchar(50), GioiTinh nvarchar(3), NgaySinh datetime, MaKhoa char(4))

• KETQUA (MaSV, MaMH, DiemThi numeric(4,2))

Yêu cầu cần làm:

  1. Viết lệnh T-SQL tạo CSDL QL_DIEM và các bảng với ràng buộc:
    • Khóa chính cho từng bảng.
    • Khóa ngoại liên kết giữa các bảng.
    • Điểm thi trong bảng KETQUA phải từ 0 đến 10 (CHECK).
    • Giới tính sinh viên có giá trị ngầm định là 'Nữ' (DEFAULT).
  2. Liệt kê sinh viên gồm: MaSV, HoTen, TenKhoa, TenMH, DiemThi của những môn có DiemThi >= 8.0.
  3. Tính điểm trung bình của từng sinh viên. Chỉ hiển thị những sinh viên có DiemTB >= 7.0 (dùng GROUP BY và HAVING).
  4. Tạo khung nhìn vw_SinhVienXuatSac hiển thị các sinh viên có điểm thi môn 'CSDL' cao nhất lớp.
Đề Số 02 Hạn nộp: Buổi học kế tiếp

Quản Lý Mượn Trả Thư Viện (QL_THUVIEN)

Cho lược đồ cơ sở dữ liệu gồm 4 bảng sau:

• DOCGIA (MaDG char(6), TenDG nvarchar(50), NgaySinh datetime, DiaChi nvarchar(100))

• SACH (MaSach char(6), TenSach nvarchar(100), TacGia nvarchar(50), SoLuongTon int)

• PHIEUMUON (MaPhieu int identity(1,1), NgayMuon datetime, MaDG char(6))

• CHITIETMUON (MaPhieu, MaSach, NgayTra datetime, TinhTrang nvarchar(50))

Yêu cầu cần làm:

  1. Viết lệnh tạo CSDL QL_THUVIEN và các bảng với ràng buộc:
    • Khóa chính, khóa ngoại liên kết.
    • Số lượng tồn của sách phải >= 0 (CHECK).
    • Ngày mượn sách có giá trị ngầm định là ngày hiện hành (DEFAULT GETDATE()).
  2. Viết Stored Procedure sp_MuonSach nhận vào @MaDG, @MaSach:
    • Kiểm tra xem sách có còn tồn kho không (SoLuongTon > 0). Nếu hết, xuất thông báo và dừng thủ tục.
    • Nếu còn, tự động giảm SoLuongTon đi 1 và thêm bản ghi vào phiếu mượn.
  3. Tạo thiết bị sao lưu logic thietbi_backup_thuvien và viết kịch bản Full Backup.

Cẩm Nang Chẩn Đoán & Sửa Nhanh 10+ Lỗi T-SQL Kinh Điển

Tổng hợp chi tiết mã lỗi, thông điệp hệ thống và phương án xử lý dứt điểm khi thực hành trên SQL Query Analyzer / SSMS.

1 Lỗi Xung Đột Khóa Ngoại (Foreign Key Violation)

Msg 547: "The INSERT statement conflicted with the FOREIGN KEY constraint..."

Nguyên nhân: Chèn mã đơn vị vào bảng con mà bảng cha chưa hề có mã này, hoặc thứ tự tạo bảng bị ngược.
Cách sửa: Luôn INSERT dữ liệu bảng cha trước; kiểm tra xem giá trị FK có tồn tại ở PK bảng cha chưa.
2 Lỗi Thiếu Cột Trong Mệnh Đề GROUP BY

Msg 8120: "Column '...' is invalid in the select list because it is not contained in GROUP BY..."

Nguyên nhân: SELECT một cột độc lập nhưng quên không đưa cột đó vào danh sách sau GROUP BY.
Cách sửa: Bất kỳ cột nào nằm ở SELECT mà không có hàm nhóm (SUM, AVG...) thì bắt buộc phải đưa vào sau GROUP BY.
3 Lỗi CSDL Đang Được Sử Dụng (Database in Use)

Msg 3702 / 3101: "Cannot drop/restore database '...' because it is currently in use."

Nguyên nhân: Cửa sổ truy vấn hoặc ứng dụng khác đang kết nối mở vào CSDL bạn muốn DROP hoặc RESTORE.
Cách sửa: Chạy USE master; GO hoặc đặt ALTER DATABASE CSDL SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
4 Lỗi Thiết Bị Sao Lưu (Device Error / Off-line)

Msg 3201: "Cannot open backup device '...'. Operating system error 3(The system cannot find the path specified)."

Nguyên nhân: Thư mục chứa file (ví dụ: C:\Backup) chưa được tạo thủ công ngoài Windows Explorer.
Cách sửa: Mở My Computer → Vào ổ C → Tạo thư mục có tên Backup trước khi chạy lệnh.
5 Lỗi Chèn Dữ Liệu Vào Cột IDENTITY

Msg 544: "Cannot insert explicit value for identity column in table '...' when IDENTITY_INSERT is set to OFF."

Nguyên nhân: Cố tình gõ giá trị cho cột tự tăng trong câu lệnh INSERT.
Cách sửa: Bỏ qua cột IDENTITY trong danh sách cột của INSERT để SQL Server tự động đánh số.
6 Lỗi Subquery Trả Về Nhiều Hơn 1 Giá Trị

Msg 512: "Subquery returned more than 1 value. This is not permitted when the subquery follows =, !=, <, >..."

Nguyên nhân: Dùng toán tử so sánh đơn (=, >) với câu truy vấn con trả về cả một danh sách nhiều hàng.
Cách sửa: Thay bằng toán tử tập hợp như IN, > ALL, hoặc > ANY.
