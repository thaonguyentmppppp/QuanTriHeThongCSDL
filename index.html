SQL Server / T-SQL Giáo Trình Chuẩn

Kiến Trúc Vận Hành & Bản Chất SQL Server Chuyên Sâu

Hệ thống hóa toàn bộ cấu trúc vật lý, cơ chế nhật ký ghi trước (WAL), các ràng buộc toàn vẹn, nguyên lý thực thi logic SELECT và giải thuật sao lưu/phục hồi theo giáo trình.

1 Cấu Trúc Vật Lý & Cơ Chế Write-Ahead Logging (WAL)

Primary Data File (.mdf)

Chứa toàn bộ dữ liệu người dùng, đối tượng bảng (Tables), chỉ mục (Indexes) và các bảng hệ thống (System Tables). Kích thước khởi tạo ban đầu tối thiểu bằng CSDL model (khoảng 1.5MB).

Transaction Log (.ldf)

Lưu lại toàn bộ lịch sử các thao tác làm biến đổi dữ liệu (INSERT, UPDATE, DELETE). Đóng vai trò sống còn trong việc khôi phục Roll Forward và Roll Back khi hệ thống bị sập nguồn đột ngột.

Page (8KB) & Extent (64KB)

Dữ liệu được tổ chức thành từng trang Page 8KB. Cứ 8 trang liên tục tạo thành một Extent. Gồm Mixed Extent (chứa dữ liệu của nhiều bảng) và Uniform Extent (dành riêng cho một bảng khi phình to).

Tiến Trình Xử Lý Giao Tác & Checkpoint:

  1. Bước 1: Ứng dụng gửi yêu cầu DML, SQL Server nạp trang dữ liệu tương ứng lên bộ nhớ RAM (gọi là Data Cache), các trang bị thay đổi gọi là dirty-page.
  2. Bước 2 (Write-Ahead): Mọi thay đổi bắt buộc phải được ghi ngay vào file .ldf (Transaction Log) trên đĩa cứng trước.
  3. Bước 3 (Checkpoint): Tiến trình Checkpoint Process định kỳ quét các dirty-page đã commit (hoàn tất) và đẩy xuống file .mdf.
  4. Khôi phục sự cố: Khi máy khởi động lại sau sự cố, giao dịch commit sau checkpoint sẽ được Roll Forward từ log file; giao dịch chưa commit sẽ bị Roll Back để trả về trạng thái nguyên vẹn.

2 Bảng Tra Cứu Các Ràng Buộc Toàn Vẹn Dữ Liệu (Constraints)

Tên Ràng Buộc Cú Pháp Định Nghĩa Chuẩn Bản Chất Hệ Thống & Đặc Điểm Cần Nhớ
PRIMARY KEY CONSTRAINT PK_Ten PRIMARY KEY (Cot) Định danh duy nhất bản ghi; bắt buộc NOT NULL; mỗi bảng duy nhất 1 khóa chính; mặc định tạo chỉ mục Clustered Index.
FOREIGN KEY CONSTRAINT FK_Ten FOREIGN KEY (Cot) REFERENCES BangCha(CotCha) Bảo toàn tham chiếu 2 bảng; giá trị phải tồn tại ở bảng cha hoặc là NULL. Bảng cha phải tạo trước bảng con.
CHECK CONSTRAINT CK_Ten CHECK (Biểu_thức_logic) Kiểm tra giá trị nhập vào theo quy tắc (ví dụ: Luong > 500 hoặc Diem BETWEEN 0 AND 10).
DEFAULT CONSTRAINT DF_Ten DEFAULT 'GiaTri' FOR Cot Tự động gán giá trị mặc định khi người dùng INSERT mà để trống. Không can thiệp vào lệnh UPDATE.
UNIQUE CONSTRAINT UNQ_Ten UNIQUE (Cot) Bảo đảm giá trị không trùng lặp; 1 bảng có thể có nhiều UNIQUE; cho phép chứa giá trị NULL.
IDENTITY Cot KieuSo IDENTITY(seed, increment) Tự động sinh số tăng dần (ví dụ IDENTITY(1,1) bắt đầu từ 1, tăng 1); người dùng không được gõ giá trị thủ công.

3 Thứ Tự Xử Lý Logic Của Câu Lệnh SELECT

SQL Server thực thi các mệnh đề theo thứ tự logic bên dưới chứ không theo thứ tự viết code:

[1] FROM & JOINXác định bảng nguồn
[2] WHERELọc từng dòng đơn lẻ
[3] GROUP BYChia nhóm dữ liệu
[4] HAVINGLọc trên nhóm (hàm aggregate)
[5] SELECTTrích xuất cột & tính toán AS
[6] ORDER BYSắp xếp tăng/giảm dần

4 Phân Biệt Cốt Tử: WHERE vs HAVING

Mệnh đề WHERE:

Lọc các hàng dữ liệu đơn lẻ trước khi phân nhóm. CẤM TUYỆT ĐỐI đưa các hàm nhóm (như AVG(), SUM(), COUNT()) trực tiếp vào WHERE.

Mệnh đề HAVING:

Lọc các nhóm dữ liệu sau khi đã thực thi GROUP BY. Được thiết kế chuyên biệt để kiểm tra kết quả của hàm nhóm (ví dụ: HAVING AVG(Luong) > 600).

Quy tắc vàng: Bất kỳ cột nào nằm ở SELECT mà không nằm trong hàm nhóm thì bắt buộc phải có mặt sau mệnh đề GROUP BY.

Bài Mẫu Hướng Dẫn Từng Dòng Lệnh

Mô Hình: Quản Lý Bán Hàng & Kho Hàng (LOAIHANG - SANPHAM)

Mục tiêu bài mẫu: Hướng dẫn học viên hoàn chỉnh luồng nghiệp vụ: Khởi tạo Database sạch → Định nghĩa cấu trúc bảng cha - con có đầy đủ 5 loại ràng buộc toàn vẹn → Nạp dữ liệu chuẩn → Viết truy vấn JOIN, GROUP BY, HAVING, SUBQUERY → Tạo View bảo mật → Viết Stored Procedure kiểm tra ràng buộc logic trước khi sửa đổi.

-- ============================================================
-- PHẦN 2: TẠO BẢNG CHA & BẢNG CON VỚI ĐỦ CÁC RÀNG BUỘC
-- ============================================================

-- Bảng cha: LOAIHANG (phải tạo trước vì bảng SANPHAM sẽ tham chiếu tới)
CREATE TABLE LOAIHANG (
    MaLoai char(4) NOT NULL,
    TenLoai nvarchar(50) NOT NULL,
    -- Ràng buộc Khóa chính (Primary Key)
    CONSTRAINT PK_LOAIHANG PRIMARY KEY (MaLoai)
);
GO

-- Bảng con: SANPHAM
CREATE TABLE SANPHAM (
    -- IDENTITY(1,1): Tự động sinh mã từ 1, tăng 1 mỗi khi thêm dòng mới
    MaSP int IDENTITY(1,1) NOT NULL,
    TenSP nvarchar(100) NOT NULL,
    DonGia numeric(10,2) NOT NULL,
    SoLuongTon int NOT NULL,
    MaLoai char(4) NULL,
    
    -- Định nghĩa các ràng buộc toàn vẹn có đặt tên chuẩn:
    CONSTRAINT PK_SANPHAM PRIMARY KEY (MaSP),                                    -- Khóa chính
    CONSTRAINT CK_SP_DonGia CHECK (DonGia > 0),                                 -- Kiểm tra đơn giá phải > 0
    CONSTRAINT DF_SP_SoLuongTon DEFAULT 0 FOR SoLuongTon,                       -- Ngầm định tồn kho là 0 nếu để trống
    CONSTRAINT FK_SANPHAM_LOAIHANG FOREIGN KEY (MaLoai) REFERENCES LOAIHANG(MaLoai) -- Khóa ngoại liên kết
);
GO

-- ============================================================
-- PHẦN 4: TRUY VẤN NÂNG CAO (JOIN, GROUP BY, HAVING, SUBQUERY)
-- ============================================================

-- [Truy vấn 1]: Nối bảng INNER JOIN có điều kiện lọc WHERE & ORDER BY
SELECT 
    SP.MaSP,
    SP.TenSP,
    SP.DonGia,
    LH.TenLoai
FROM SANPHAM SP
INNER JOIN LOAIHANG LH ON SP.MaLoai = LH.MaLoai -- Nối theo cặp khóa
WHERE SP.DonGia >= 400.00                       -- Lọc đơn giá >= 400
ORDER BY SP.DonGia DESC;                         -- Sắp xếp giảm dần
GO

-- [Truy vấn 2]: Gom nhóm GROUP BY kèm HAVING
-- Đếm số mặt hàng, tính đơn giá TB và tổng trị giá tồn kho của từng loại
SELECT 
    LH.TenLoai,
    COUNT(SP.MaSP) AS TongSoMatHang,
    AVG(SP.DonGia) AS DonGiaTrungBinh,
    SUM(SP.DonGia * SP.SoLuongTon) AS TongGiaTriTonKho
FROM LOAIHANG LH
INNER JOIN SANPHAM SP ON LH.MaLoai = SP.MaLoai
GROUP BY LH.TenLoai
HAVING COUNT(SP.MaSP) >= 2;                     -- Chỉ lấy loại nào có từ 2 mặt hàng trở lên
GO

-- [Truy vấn 3]: Truy vấn con lồng nhau (Subquery)
-- Tìm các sản phẩm có đơn giá cao hơn mức giá trung bình của toàn bộ cửa hàng
SELECT 
    MaSP,
    TenSP,
    DonGia
FROM SANPHAM
WHERE DonGia > (
    SELECT AVG(DonGia) 
    FROM SANPHAM
);
GO

-- ============================================================
-- PHẦN 5: TẠO KHUNG NHÌN (VIEW) BẢO MẬT DỮ LIỆU
-- ============================================================
CREATE VIEW vw_BaoCaoKhoHang (MaLoai, TenLoai, SoLuongSanPham, TongTonKho)
AS
SELECT 
    LH.MaLoai,
    LH.TenLoai,
    COUNT(SP.MaSP),
    SUM(SP.SoLuongTon)
FROM LOAIHANG LH
LEFT JOIN SANPHAM SP ON LH.MaLoai = SP.MaLoai
GROUP BY LH.MaLoai, LH.TenLoai;
GO

-- Kiểm tra truy vấn từ View
SELECT * FROM vw_BaoCaoKhoHang;
GO

-- ============================================================
-- PHẦN 6: STORED PROCEDURE CẬP NHẬT GIÁ CÓ BẪY LỖI
-- ============================================================
CREATE PROCEDURE sp_CapNhatGiaBan
    @p_MaSP int,
    @p_DonGiaMoi numeric(10,2)
AS
BEGIN
    SET NOCOUNT ON;

    -- Kiểm tra 1: Xác thực đơn giá mới nhập
    IF (@p_DonGiaMoi <= 0)
    BEGIN
        PRINT N'Thao tác thất bại: Đơn giá mới phải lớn hơn 0!';
        RETURN;
    END;

    -- Kiểm tra 2: Kiểm tra sự tồn tại của sản phẩm
    IF NOT EXISTS (SELECT 1 FROM SANPHAM WHERE MaSP = @p_MaSP)
    BEGIN
        PRINT N'Thao tác thất bại: Sản phẩm mang mã số này không tồn tại!';
        RETURN;
    END;

    -- Cập nhật dữ liệu
    UPDATE SANPHAM
    SET DonGia = @p_DonGiaMoi
    WHERE MaSP = @p_MaSP;

    PRINT N'Xác nhận: Đã cập nhật đơn giá mới cho sản phẩm thành công!';
END;
GO

-- Thử nghiệm gọi thủ tục cập nhật giá
EXEC sp_CapNhatGiaBan @p_MaSP = 1, @p_DonGiaMoi = 350.00;
GO

-- Kiểm tra lại sản phẩm vừa sửa
SELECT MaSP, TenSP, DonGia FROM SANPHAM WHERE MaSP = 1;
GO

Truy Vấn T-SQL & Xây Dựng Khung Nhìn (VIEW)

Yêu cầu cần đạt:

  • Truy vấn kết nối INNER JOIN nhân viên và đơn vị có lương >= 600.
  • Gom nhóm GROUP BY đơn vị có lương TB > 600 (dùng HAVING).
  • Truy vấn lồng: Lương > trung bình công ty, lương > ALL đơn vị '02'.
  • Tạo 2 khung nhìn: vw_NhanVien_DonVi và vw_ThongKeDonVi.
USE QL_CONGTY;
GO

-- 1. INNER JOIN
SELECT NV.HoTen, NV.Luong, DV.TenDV
FROM NHANVIEN NV
INNER JOIN DONVI DV ON NV.MaDV = DV.MaDV
WHERE NV.Luong >= 600;
GO

-- 2. GROUP BY & HAVING
SELECT MaDV, MAX(Luong) AS MaxLuong, AVG(Luong) AS LuongTB
FROM NHANVIEN
GROUP BY MaDV
HAVING AVG(Luong) > 600;
GO

-- 3. SUBQUERY
SELECT MaNV, HoTen, Luong
FROM NHANVIEN
WHERE Luong > (SELECT AVG(Luong) FROM NHANVIEN);
GO

SELECT MaNV, HoTen, Luong
FROM NHANVIEN
WHERE Luong > ALL (
    SELECT Luong 
    FROM NHANVIEN 
    WHERE MaDV = '02'
);
GO

-- 4. VIEW
CREATE VIEW vw_NhanVien_DonVi
AS
SELECT NV.MaNV, NV.HoTen, DV.TenDV, NV.Luong
FROM NHANVIEN NV
INNER JOIN DONVI DV ON NV.MaDV = DV.MaDV;
GO

CREATE VIEW vw_ThongKeDonVi (TenDV, SoNhanVien, TongLuong)
AS
SELECT DV.TenDV, COUNT(NV.MaNV), SUM(NV.Luong)
FROM DONVI DV
INNER JOIN NHANVIEN NV ON DV.MaDV = NV.MaDV
GROUP BY DV.TenDV;
GO

SELECT * FROM vw_ThongKeDonVi;
GO

Stored Procedure & Quản Trị Backup/Restore

Yêu cầu cần đạt:

  • Viết Stored Procedure sp_ThemNhanVien có kiểm tra tính hợp lệ của lương trước khi INSERT.
  • Tạo Backup Device logic: thietbi_backup_congty qua sp_addumpdevice.
  • Thực hiện lệnh Full Backup (vào Device và trực tiếp ra tệp tin .BAK).
  • Thực hiện lệnh RESTORE DATABASE WITH REPLACE để khôi phục trạng thái.
USE QL_CONGTY;
GO

-- 1. Stored Procedure
CREATE PROCEDURE sp_ThemNhanVien
    @MaNV char(10),
    @HoTen nvarchar(50),
    @Luong numeric(10,2),
    @MaDV char(2)
AS
BEGIN
    IF (@Luong <= 500)
    BEGIN
        PRINT N'Lỗi: Lương nhân viên phải lớn hơn 500!';
        RETURN;
    END

    INSERT INTO NHANVIEN (MaNV, HoTen, Luong, MaDV)
    VALUES (@MaNV, @HoTen, @Luong, @MaDV);

    PRINT N'Thêm nhân viên mới thành công!';
END;
GO

EXEC sp_ThemNhanVien 'NV099', N'Trần Văn An', 750, '01';
GO

-- 2. Tạo thiết bị Backup logic
USE master;
GO
EXEC sp_addumpdevice 'disk', 'thietbi_backup_congty', 'C:\Backup\QL_CONGTY.BAK';
GO

-- 3. Sao lưu Full Database
BACKUP DATABASE QL_CONGTY 
TO thietbi_backup_congty 
WITH INIT;
GO

BACKUP DATABASE QL_CONGTY 
TO DISK = N'C:\Backup\QL_CONGTY_Full.bak' 
WITH INIT;
GO

-- 4. Phục hồi dữ liệu
USE master;
GO
RESTORE DATABASE QL_CONGTY 
FROM thietbi_backup_congty 
WITH REPLACE;
GO

Bài Tập Tự Luyện Về Nhà (Không Kèm Code Mẫu)

Sinh viên tự đọc yêu cầu, phân tích lược đồ quan hệ và tự hoàn thiện câu lệnh T-SQL vào khung làm bài bên dưới. Sau khi hoàn thành, nhấn nút "Tải File .SQL Nộp Bài" để gửi cho giảng viên.

Đề Số 01 Hạn nộp: Buổi học kế tiếp

Quản Lý Điểm Sinh Viên (QL_DIEM)

Cho lược đồ cơ sở dữ liệu gồm 4 bảng sau:

• KHOA (MaKhoa char(4), TenKhoa nvarchar(50))

• MONHOC (MaMH char(4), TenMH nvarchar(50), SoTinChi int)

• SINHVIEN (MaSV char(10), HoTen nvarchar(50), GioiTinh nvarchar(3), NgaySinh datetime, MaKhoa char(4))

• KETQUA (MaSV, MaMH, DiemThi numeric(4,2))

Yêu cầu cần làm:

  1. Viết lệnh T-SQL tạo CSDL QL_DIEM và các bảng với ràng buộc:
    • Khóa chính cho từng bảng.
    • Khóa ngoại liên kết giữa các bảng.
    • Điểm thi trong bảng KETQUA phải từ 0 đến 10 (CHECK).
    • Giới tính sinh viên có giá trị ngầm định là 'Nữ' (DEFAULT).
  2. Liệt kê sinh viên gồm: MaSV, HoTen, TenKhoa, TenMH, DiemThi của những môn có DiemThi >= 8.0.
  3. Tính điểm trung bình của từng sinh viên. Chỉ hiển thị những sinh viên có DiemTB >= 7.0 (dùng GROUP BY và HAVING).
  4. Tạo khung nhìn vw_SinhVienXuatSac hiển thị các sinh viên có điểm thi môn 'CSDL' cao nhất lớp.
Đề Số 02 Hạn nộp: Buổi học kế tiếp

Quản Lý Mượn Trả Thư Viện (QL_THUVIEN)

Cho lược đồ cơ sở dữ liệu gồm 4 bảng sau:

• DOCGIA (MaDG char(6), TenDG nvarchar(50), NgaySinh datetime, DiaChi nvarchar(100))

• SACH (MaSach char(6), TenSach nvarchar(100), TacGia nvarchar(50), SoLuongTon int)

• PHIEUMUON (MaPhieu int identity(1,1), NgayMuon datetime, MaDG char(6))

• CHITIETMUON (MaPhieu, MaSach, NgayTra datetime, TinhTrang nvarchar(50))

Yêu cầu cần làm:

  1. Viết lệnh tạo CSDL QL_THUVIEN và các bảng với ràng buộc:
    • Khóa chính, khóa ngoại liên kết.
    • Số lượng tồn của sách phải >= 0 (CHECK).
    • Ngày mượn sách có giá trị ngầm định là ngày hiện hành (DEFAULT GETDATE()).
  2. Viết Stored Procedure sp_MuonSach nhận vào @MaDG, @MaSach:
    • Kiểm tra xem sách có còn tồn kho không (SoLuongTon > 0). Nếu hết, xuất thông báo và dừng thủ tục.
    • Nếu còn, tự động giảm SoLuongTon đi 1 và thêm bản ghi vào phiếu mượn.
  3. Tạo thiết bị sao lưu logic thietbi_backup_thuvien và viết kịch bản Full Backup.

Top Các Lỗi Sinh Viên Thường Gặp Khi Thực Hành & Cách Xử Lý

Tổng hợp các thông báo lỗi kinh điển trong SQL Query Analyzer / SSMS và giải pháp khắc phục triệt để.

1. Lỗi: "The INSERT statement conflicted with the FOREIGN KEY constraint..."

Nguyên nhân: Bạn đang cố chèn một bản ghi vào bảng con (ví dụ: NHANVIEN) với mã đơn vị không hề tồn tại trong bảng cha (DONVI), hoặc thứ tự INSERT dữ liệu bị ngược.

Khắc phục: Luôn tạo bảng cha trước, bảng con sau. Khi nạp dữ liệu, phải chèn đầy đủ danh sách mã vào bảng cha trước rồi mới chèn dữ liệu bảng con.

2. Lỗi: "...is invalid in the select list because it is not contained in either an aggregate function or the GROUP BY clause"

Nguyên nhân: Trong mệnh đề SELECT bạn có liệt kê các cột đơn lẻ nhưng lại quên không đưa các cột này vào danh sách sau mệnh đề GROUP BY.

Khắc phục: Quy tắc bất di bất dịch: Bất kỳ cột nào nằm ở SELECT mà không có hàm nhóm bao bọc (như COUNT, SUM, AVG, MAX, MIN) thì bắt buộc phải xuất hiện sau GROUP BY.

3. Lỗi: "Cannot drop database '...' because it is currently in use"

Nguyên nhân: Bạn đang đứng ngay trong chính CSDL đó để gõ lệnh DROP DATABASE hoặc RESTORE DATABASE.

Khắc phục: Chuyển ngữ cảnh làm việc về cơ sở dữ liệu hệ thống trước bằng lệnh: USE master; GO rồi mới thực thi lệnh xóa hoặc phục hồi.

4. Lỗi: "Device error or device off-line" khi tạo Backup Device

Nguyên nhân: Đường dẫn thư mục vật lý (ví dụ: C:\Backup) chưa được tạo trên Windows, hoặc SQL Server không có quyền ghi file.

Khắc phục: Vào File Explorer của Windows, tạo sẵn thư mục C:\Backup (hoặc ổ D:\Backup) trước khi chạy thủ tục sp_addumpdevice.
